# StreamMQ 业务逻辑混乱/歧义审查报告

> 审查视角：以开源项目发布标准，全面否定性审查项目中的业务逻辑混乱和歧义问题
> 审查日期：2026-07-21
> 审查结论：**发现 12 项业务逻辑问题（4 项严重 / 5 项重要 / 3 项一般）**

---

## 一、严重问题（必须修复）

### 1.1 事务消息的"简化模式"与"完整模式"语义不清

**位置**：`streammq-core/.../template/StreamMessageTemplate.java`、`DefaultStreamMessageTemplate.java`

**问题描述**：
`StreamMessageTemplate` 提供了两种事务消息发送方式：

1. **简化模式**：`executeInTransaction(Message, TransactionCallback)` - 在当前线程执行本地事务
2. **完整模式**：使用 `TransactionScanner` 进行半消息 + 回查

但两者的行为差异未在 API 和文档中明确说明：

```java
// 简化模式 - 用户看到的方法签名
<T> SendResult executeInTransaction(Message<T> message, TransactionCallback<T> callback);

// 完整模式 - 需要配置 TransactionScanner
// 用户需要知道要配置 transaction.default-group 才能使用
```

**歧义点**：
- 什么时候用简化模式？什么时候用完整模式？
- 简化模式下如果本地事务执行过程中 JVM 崩溃，消息会怎样？
- 两种模式的可靠性保证分别是什么？

**影响**：
- 用户无法根据业务场景选择正确的事务模式
- 在需要可靠事务保证的场景下使用了简化模式，导致数据不一致

---

### 1.2 ConsumeAction 和 OrderlyAction 的语义分裂

**位置**：`streammq-core/.../enums/ConsumeAction.java`、`OrderlyAction.java`

**问题描述**：
并发消费返回 `ConsumeAction`（SUCCESS / RECONSUME_LATER / DEFER），顺序消费返回 `OrderlyAction`（SUCCESS / SUSPEND_CURRENT_QUEUE_A_MOMENT）。两套 API 语义不同但表达的意图类似：

| 并发消费 | 顺序消费 | 语义差异 |
|---------|---------|---------|
| SUCCESS | SUCCESS | 一致 |
| RECONSUME_LATER | SUSPEND_CURRENT_QUEUE_A_MOMENT | 本质都是重试，但触发的行为不同 |
| DEFER(Duration) | 无 | 并发消费支持自定义延迟，顺序消费不支持 |

**歧义点**：
- `SUSPEND_CURRENT_QUEUE_A_MOMENT` 暂停多久？"A MOMENT" 是多长？
- 为什么顺序消费不支持 DEFER？
- 用户从并发消费迁移到顺序消费时，RECONSUME_LATER 的行为会悄然改变

---

### 1.3 消息 Key 的多义性

**位置**：`streammq-core/.../message/Message.java`

**问题描述**：
`Message` 类中有三个看似相关的字段：

```java
private String keys;        // 消息唯一标识（对齐 RocketMQ 的 keys）
private String messageId;   // 框架生成的消息 ID
private String shardingKey; // 分片键（用于顺序消费）
```

**歧义点**：
- `keys` 和 `messageId` 的区别是什么？用户应该用哪个来唯一标识消息？
- `keys` 是必填还是选填？如果不填会有什么影响？
- `shardingKey` 是否可以和 `keys` 相同？什么场景下需要不同的值？
- 文档中"keys"被描述为"消息 Key（用于查询和去重）"，但去重逻辑在哪里？

**影响**：
- 用户不知道应该设置哪个字段
- 日志中输出 `keys` 还是 `messageId` 不一致
- 去重功能未明确实现，但文档暗示存在

---

### 1.4 DLQ 消费者与普通消费者的注册逻辑混乱

**位置**：`streammq-spring-boot-starter/.../StreamMQListenerRegistrar.java`

**问题描述**：
DLQ 消费者通过 `@StreamMQConsumer(dlqMode = true)` 注册，与普通消费者使用同一个注解。但注册逻辑中有微妙的差异：

```java
if (resolved.dlqMode()) {
    LOG.info("Registered DlqConsumer: bean={}, topic={}, group={}",
        beanName, resolved.topic(), resolved.consumerGroup());
} else {
    LOG.info("Registered Consumer: bean={}, topic={}, group={}",
        beanName, resolved.topic(), resolved.consumerGroup());
}
```

日志中区分了 DlqConsumer 和 Consumer，但注册到 `listenerContainer` 的方法都是 `registerConsumer()`。

**歧义点**：
- DLQ 消费者和普通消费者的内部处理逻辑是否有差异？
- DLQ 消费者消费失败后会怎样？会再次进入 DLQ 导致无限循环吗？
- DLQ 消费者的 topic 是什么？是原始 topic 还是 DLQ topic？

## 二、重要问题（应该修复）

### 2.1 延时消息的两种方式行为不一致

**位置**：`streammq-core/.../message/Message.java`

**问题描述**：
```java
private DelayLevel delayLevel;      // 18 级固定延时
private Long delayTimeMillis;       // 任意毫秒延时
```

**歧义点**：
- 同时设置 `delayLevel` 和 `delayTimeMillis` 时，哪个生效？
- 两种延时方式的实现机制不同（18 级用 Redis Stream Consumer Group 延迟投递，任意毫秒用 ScoredSortedSet），这是否意味着它们的可靠性不同？
- 18 级延时消息的精度是多少？是精确到秒还是有误差？

---

### 2.2 Namespace 的作用域定义模糊

**位置**：`streammq-core/.../annotation/StreamMQConsumer.java`、`StreamMQProperties.java`

**问题描述**：
`namespace` 用于区分不同环境/租户的 Stream Key，但其作用域不清晰：

```java
// 注解中的 namespace
@StreamMQConsumer(topic = "order", namespace = "prod")

// 配置文件中的 namespace
streammq:
  namespace: streammq
```

**歧义点**：
- 注解中的 `namespace` 和配置文件中的 `namespace` 优先级是什么？
- 不同 namespace 下的消息是否完全隔离？
- namespace 是否影响 Consumer Group 的命名？
- 文档中说"namespace 用于避免 Key 冲突"，但没有说明具体的 Key 生成规则

---

### 2.3 Producer Group 和 Consumer Group 的命名规则未定义

**问题描述**：
项目中大量使用 Group 概念（Producer Group、Consumer Group、Transaction Group），但没有定义：
- Group 名称的合法字符范围
- Group 名称的最大长度
- Group 名称是否支持中文/特殊字符
- 不同 Group 之间的命名冲突处理

**影响**：
- 用户可能使用包含非法字符的 Group 名称导致 Redis 操作失败
- 在多团队共享 Redis 时可能出现命名冲突

---

### 2.4 消息发送的返回值语义不明确

**位置**：`streammq-core/.../message/SendResult.java`

**问题描述**：
`SendResult` 的字段和语义未在代码中充分文档化。用户不知道：
- `SendResult` 是否表示消息已持久化到 Redis？
- 还是仅表示消息已发送到 Redisson 客户端的缓冲区？
- 在 Redis 主从异步复制模式下，`SendResult` 是否保证消息不会丢失？

---

### 2.5 ConsumerFilter 和 SelectorExpression 的关系混乱

**位置**：`streammq-core/.../filter/` 目录

**问题描述**：
项目中有两套过滤机制：
1. **SelectorExpression**：在注解中配置 `selectorExpression` 和 `selectorType`
2. **ConsumerFilter SPI**：通过 `consumerFilter` 属性配置自定义过滤器

**歧义点**：
- 两套机制的关系是什么？是串联还是并联？
- `selectorExpression` 内部是否通过 `ConsumerFilter` 实现？
- 如果用户同时配置了 `selectorExpression` 和 `consumerFilter`，执行顺序是什么？
- 代码中 `TagSelectorFilter` 和 `SqlSelectorFilter` 是 `ConsumerFilter` 的子类，但它们通过 `ExpressionSelectorFilter` 接口关联，关系复杂

## 三、一般问题（建议修复）

### 3.1 消息 BornTimestamp 和 BornHost 的用途不明

**位置**：`streammq-core/.../message/Message.java`

```java
private long bornTimestamp;   // 消息创建时间
private String bornHost;      // 消息创建主机
```

**问题描述**：
这两个字段在 RocketMQ 中用于消息溯源，但在 StreamMQ 中：
- `bornHost` 在分布式环境中通常没有实际意义（IP 地址不是唯一标识）
- 两个字段在消费端几乎不被使用
- 文档中未说明其用途和使用场景

---

### 3.2 ReconsumeTimes 字段的管理混乱

**位置**：`streammq-core/.../message/Message.java`

```java
private int reconsumeTimes;  // 已重试次数
```

**问题描述**：
- 这个字段是在消息创建时设置的，还是框架在重试时自动递增的？
- 在 `MessageBuilder` 中是否应该暴露 `reconsumeTimes()` 方法？
- 如果用户手动设置了 `reconsumeTimes`，会覆盖框架的重试计数吗？

---

### 3.3 配置项命名风格不统一

**位置**：`streammq-spring-boot-starter/.../StreamMQProperties.java`

**问题描述**：
配置项命名混合了多种风格：

```yaml
streammq:
  namespace: streammq           # 单词
  producer:
    group: default-group        # 单词
    send-timeout: 3000          # kebab-case
    stream-max-len: 0           # kebab-case
  consumer:
    consume-thread-min: 1       # 三段式
    consume-thread-max: 64      # 三段式
    pull-batch-size: 32         # 三段式
    max-reconsume-times: 16     # 四段式（过长）
    inflight-capacity: 1000     # 单词+连字符
```
